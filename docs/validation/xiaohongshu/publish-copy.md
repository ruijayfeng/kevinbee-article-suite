# 发布文案与制作元数据分离

2026-10-05 的实际制作发现：普通插画被加上“概念示意”等标签。标签来自逐页 Text Content，并非工具擅自增加；上游“分开标注”的规则没有指明记录位置，套件复核也未检查这类泄漏。

修复将 Evidence Status 定义为制作元数据，提示词明确发布文案与制作指令的区域；必要的读者说明仍保留，并记录 Reader Disclosure 和 Disclosure Reason。上游独立检查器在出图前运行，套件核验调用同一检查器，不复制另一套关键词规则。

验证结果：

- 原实际规划拦住 6 处制作说明；去除标签后的同一份规划为 0 错误。
- 上游 4 组命令行测试通过：制作标签阻断、元数据和自然正文兼容、必要读者说明及原因、格式错误处理。
- 套件 16 组小红书测试通过，包括新增发布文案阻断和读者条件保留；原交接与回流测试通过。
- 原成图、候选、原始输出与旧交付包保留；当前交付仅重新生成受影响的 5 页。实际生成记录与作者稿不进入公开仓库。

脚本检查规划文本，不能识别模型在图片里额外生成的文字；生成后仍须逐字复核发布文案、检查素材性质和手机阅读。必要条件、来源或测试边界不能因清理标签而丢失。
